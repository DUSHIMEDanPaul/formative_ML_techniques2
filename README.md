# Human Activity Recognition with a Hidden Markov Model

This project uses smartphone accelerometer and gyroscope recordings to classify four human activity states:

- Still
- Standing
- Walking
- Jumping

The complete workflow is implemented in [hmm_activity_recognition.ipynb](hmm_activity_recognition.ipynb). It builds a Gaussian Hidden Markov Model (HMM) from scratch with NumPy, without using a machine-learning HMM library.

## Project workflow

The notebook runs the following pipeline:

1. Read Sensor Logger ZIP exports.
2. Clean and harmonize accelerometer, gyroscope, and total-acceleration signals.
3. Resample all sensors to 50 Hz.
4. Split recordings into overlapping 2.56-second windows.
5. Extract time-domain and frequency-domain features.
6. Apply log transforms and Z-score normalization.
7. Split recordings into training and validation sets without mixing windows from the same recording.
8. Initialize and train a full-covariance Gaussian HMM with supervised estimates and Baum-Welch refinement.
9. Decode activity sequences with Viterbi.
10. Report accuracy, sensitivity, specificity, confusion matrices, and diagnostic plots.

## Input data

### Training recordings

Place Sensor Logger ZIP exports directly in `data/`. The notebook identifies the activity and recording number from filenames such as:

```text
Walking_thirty_one_-2026-10-28_15-57-34.zip
```

The ZIP must contain these Sensor Logger files:

```text
Accelerometer.csv
Gyroscope.csv
TotalAcceleration.csv
Metadata.csv
```

The activity prefix is mapped as follows:

| Filename prefix | Activity |
|---|---|
| `still` or `floor` | Still |
| `standing` | Standing |
| `walking` | Walking |
| `jump` or `jumping` | Jumping |

### Optional unseen test data

Put unseen Sensor Logger ZIP files in `data/test/` and create `data/test/test_labels.csv` with this format:

```csv
file,start_s,end_s,activity
Test_one-2026-10-30_10-00-00.zip,0,10,Standing
Test_one-2026-10-30_10-00-00.zip,10,20,Walking
```

`start_s` and `end_s` are measured from the beginning of the test recording. A window is assigned the label of the segment containing its center time. Unlabeled transition windows are excluded from the reported metrics.

If no test ZIP files and label file are available, the notebook evaluates on the held-out validation recordings instead.

## Running the notebook

From the project directory, start Jupyter:

```powershell
.\.venv\Scripts\Activate.ps1
jupyter notebook
```

Open `hmm_activity_recognition.ipynb` and run the cells from top to bottom. Running cells in order is important because later cells use data, features, and model objects created earlier in the notebook.

The notebook writes cleaned recordings to `dataset/` and generated figures to `figures/`, including:

- Sample cleaned signals
- Feature distributions
- Baum-Welch convergence
- HMM transition matrix
- Emission means and densities
- Confusion matrix
- Decoded activity sequences

## Model details

Each observation is a nine-dimensional feature vector calculated from a 2.56-second window:

- Linear-acceleration variability and signal magnitude area
- Gyroscope variability and signal magnitude area
- Accelerometer-axis correlation
- Phone tilt relative to gravity
- Dominant frequency
- Spectral energy
- Spectral entropy

The model uses four hidden states and multivariate Gaussian emissions with full covariance matrices. Forward-backward calculations, Baum-Welch training, and Viterbi decoding are implemented directly with NumPy in log space to reduce numerical underflow.

## Reproducibility

The notebook uses a fixed random seed (`SEED = 42`) for data splitting and chain construction. Results can still vary if the input recordings or generated data change.

## Notes

- Training recordings are split by recording rather than by individual window, preventing overlapping windows from the same clip appearing in both training and validation sets.
- Sensor streams are linearly interpolated onto a shared 50 Hz time grid.
- Accelerometer intensity features are log-transformed before normalization.
- The notebook uses only NumPy, pandas, and Matplotlib for the modeling and visualization code.
